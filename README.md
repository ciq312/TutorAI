# Tutor RAG

Помощник репетитора для быстрой подготовки к занятиям, составления домашних заданий и обратной связи после урока с учётом истории конкретного ученика.

Семантический поиск находит связанные темы и трудности в прошлых занятиях, а LLM использует этот контекст для подготовки черновиков материалов. Репетитор проверяет и редактирует результат.

## Основные сценарии

- **Перед занятием:** получить краткий бриф по ученику и план следующего урока с учётом целей, последних занятий и прошлых трудностей.
- **Домашнее задание:** подготовить задания по пройденным темам с учётом уровня ученика и ошибок, которые стоит отработать.
- **После занятия:** превратить короткие заметки репетитора в понятный фидбек для ученика или родителя.

Подробные сценарии, границы MVP, архитектура, модель данных и план разработки описаны в [PROJECT.md](PROJECT.md).

## Текущее состояние

Реализован первый этап — основа и данные:

- CRUD учеников, необязательных контактов и занятий через REST API и Swagger UI.
- История занятий по ученику, фильтрация по датам и пагинация.
- PostgreSQL, асинхронный SQLAlchemy и миграции Alembic.
- JSON-импорт демоданных и проверка доступности базы через `/health`.
- Интеграционные тесты на PostgreSQL.

Реализована основа второго этапа: индексация занятий через облачный адаптер Gemini,
поиск pgvector с источниками, статусы ошибок и повторная индексация. Для облачной
проверки нужен API-ключ. LLM и генерация материалов пока не реализованы.

## Запуск через Docker Compose

Нужны Docker и Docker Compose.

```bash
cp .env.example .env
# При необходимости измените параметры PostgreSQL в .env.
docker compose up --build -d
```

При запуске API автоматически выполняет `alembic upgrade head`. Если миграция завершается ошибкой, API не стартует. Данные PostgreSQL сохраняются в Docker volume.

- Swagger UI: http://localhost:8000/docs
- OpenAPI: http://localhost:8000/openapi.json
- Проверка API и БД: http://localhost:8000/health

Загрузить вымышленные примеры (2 ученика, 2 контакта, 6 занятий):

```bash
docker compose exec api python -m app.seed
```

Повторный импорт пропускает существующие ID и не перезаписывает правки. Можно передать путь к другому JSON в формате `data/seed.json`. Импорт валидируется и выполняется одной транзакцией.

Остановить сервисы с сохранением данных:

```bash
docker compose down
```

## Локальная разработка

Нужны Python 3.14 и PostgreSQL. Для запуска Python на хосте можно поднять только базу через Compose:

```bash
cp .env.example .env
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
docker compose up -d db
alembic upgrade head
uvicorn app.main:app --reload
```

Если `.env` уже существует, сохраните свои настройки. Для запуска на хосте `DATABASE_URL` должен указывать на `localhost`; внутри Compose адрес `db` устанавливается автоматически. При изменении пароля или имени базы согласуйте значения `POSTGRES_*` и `DATABASE_URL`. Учётные данные существующего PostgreSQL volume не меняются простым редактированием `.env`.

## Работа с API

В Swagger сначала создайте ученика через `POST /api/students`:

```json
{
  "name": "Анна",
  "grade": "8 класс",
  "goals": "Уверенно решать квадратные уравнения"
}
```

Используйте полученный `id` для `POST /api/students/{student_id}/lessons`:

```json
{
  "scheduled_at": "2026-11-14T16:00:00+03:00",
  "topic": "Квадратные уравнения",
  "notes": "Разобрали дискриминант и решили три примера.",
  "difficulties": "Теряет знак при подстановке коэффициентов.",
  "homework": "Решить пять уравнений из выданного списка."
}
```

Контакты добавляются отдельно через `POST /api/students/{student_id}/contacts`: `name`, `phone` в международном формате (например, `+12025550101`), необязательное `relationship`. Ученик может существовать без контактов.

История — `GET /api/students/{student_id}/lessons`. Она отсортирована от новых занятий к старым. Параметры `date_from` и `date_to` включают границы и требуют часовой пояс. Все списки поддерживают `limit` (1–100, по умолчанию 50) и `offset`.

В `PATCH` пропущенные поля сохраняются, а `null` очищает необязательные. `homework` означает фактически заданное ДЗ; его выполнение пока не отслеживается. Удаление ученика удаляет его контакты и занятия. Несуществующие записи возвращают `404`, неверные входные данные — `422`.

## Тесты

```bash
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Нужен работающий Docker, доступный текущему пользователю (`docker info`). Testcontainers автоматически поднимает отдельную PostgreSQL 17 на свободном порту, применяет миграции и удаляет контейнер после прогона. Первый запуск скачивает Docker-образы.

На Fedora с SELinux служебный контейнер очистки Ryuk может завершаться с `permission denied` при доступе к Docker-сокету. Для такой конфигурации:

```bash
TESTCONTAINERS_RYUK_PRIVILEGED=true python -m pytest -q
```

Этот параметр включает привилегированный режим только для Ryuk, а не для PostgreSQL.

Контейнер общий для тестовой сессии, таблицы очищаются между тестами. Проверяются также откат миграций и соответствие схемы ORM-моделям. Рабочая база, `.env` и ранее заданная `TEST_DATABASE_URL` для подключения тестов не используются. Вручную создавать БД и запускать Compose не нужно. Если Docker недоступен, интеграционные тесты завершаются ошибкой, а не пропускаются.

Для запуска одного теста:

```bash
python -m pytest tests/test_api.py::test_journal_and_partial_update -v
```

## Данные и приватность

Имена и контакты хранятся в собственной PostgreSQL. Контакты доступны через отдельные endpoints и не включаются в ответы с учебной историей. Перед отправкой embedding-провайдеру применяется базовая маскировка известных имён, email и телефоноподобных строк; ограничения описаны ниже. При использовании облачных LLM или embeddings соответствующие тексты передаются внешнему провайдеру; локальное хранение само по себе не означает локальную обработку.

Первый MVP рассчитан на личный запуск одним репетитором в доверенной среде. Авторизация и несколько пользователей запланированы отдельно.

## Поиск контекста — этап 2

Добавлены pgvector, заменяемый интерфейс embeddings и облачный адаптер Gemini
(`gemini-embedding-001`, по умолчанию 768 измерений). На старте используем бесплатный
тариф Gemini API. Нужен ключ из https://aistudio.google.com/api-keys:

```dotenv
EMBEDDING_PROVIDER=gemini
EMBEDDING_MODEL=gemini-embedding-001
EMBEDDING_DIMENSIONS=768
EMBEDDING_TIMEOUT=30
GEMINI_API_KEY=your_key
```

Укажите ключ только в локальном `.env`. Используйте проект без подключённого
биллинга, если нужна работа исключительно в рамках бесплатной квоты: приложение
не определяет тариф ключа. Квоты и доступность по регионам проверяются в AI Studio.
Тариф: https://ai.google.dev/gemini-api/docs/pricing#gemini-embedding.
Тексты бесплатного тарифа могут использоваться Google для улучшения продуктов.

Compose теперь использует `pgvector/pgvector:pg17`. Для существующего окружения:

```bash
docker compose up --build -d
```

Версия PostgreSQL остаётся 17, существующий volume сохраняется. Миграция создаёт
расширение `vector`; при собственной PostgreSQL оно должно быть установлено на
сервере, а пользователь миграций должен иметь право его создать. Рабочая база не
обновляется запуском тестов.

### Индексация

Создание занятия и изменение темы/заметок/ДЗ/трудностей запускают синхронную
индексацию в рамках запроса. Короткая запись становится одним фрагментом, длинная
разбивается на фрагменты до 1800 символов с перекрытием 200. Только изменение даты
не вызывает запрос к провайдеру. Пустой PATCH также не расходует квоту.

В ответе занятия есть `indexing_status` (`pending`, `ready`, `failed`) и
`indexing_error` — безопасный код причины. Например, `missing_api_key`,
`rate_limited`, `provider_timeout`, `provider_access_denied`. При ожидаемой ошибке
провайдера запись сохраняется, старые фрагменты удаляются, статус становится
`failed`. Ошибки базы приводят к откату всей транзакции. Индексация удерживает
блокировку занятия; очередь и worker пока не используются.

Повтор одного занятия (в том числе после смены модели):

```http
POST /api/lessons/{lesson_id}/index
```

Существующие записи и JSON seed получают статус `pending`. Индексировать их:

```bash
docker compose exec api python -m app.reindex
# Только один ученик:
docker compose exec api python -m app.reindex --student-id STUDENT_UUID
# Принудительно пересоздать совместимые готовые индексы:
docker compose exec api python -m app.reindex --force
```

Команда сохраняет результат каждого занятия отдельно, останавливается при первой
ошибке провайдера и возвращает ненулевой код. После восстановления квоты повторите
команду: готовые совместимые записи будут пропущены. Удаление занятия или ученика
каскадно удаляет фрагменты.

### Запрос контекста

```http
POST /api/students/{student_id}/context/search
Content-Type: application/json
```

```json
{
  "query": "Какие трудности были со знаками и раскрытием скобок?",
  "recent_lessons_limit": 3,
  "semantic_limit": 5,
  "max_distance": 0.7,
  "max_context_chars": 12000
}
```

Необязательные `date_from` и `date_to` включают границы, требуют часовой пояс и
применяются и к хронологии, и к семантическому поиску. Ответ содержит:

- `sources`: записи с `lesson_id`, датой, фрагментами и причинами включения
  (`recent`, `semantic` или обе). Повторяющиеся источники объединяются.
- `distance`: косинусное расстояние семантического совпадения; меньше — ближе.
  Это не вероятность правильности. Порог 0.7 предварительный и требует оценки
  на выбранной модели и реальных заметках.
- `semantic_status`: `ready`, `empty`, `unavailable` или `disabled`.
- `unindexed_lessons`: число занятий в выбранном диапазоне без совместимого
  готового индекса.
- `warnings`: `index_incomplete`, `no_context`, `context_truncated` и безопасные
  коды ошибок провайдера.

`semantic_limit=0` отключает обращение к embeddings. При пустом индексе запрос к
провайдеру также не выполняется. При недоступности провайдера последние занятия
остаются в ответе с явным предупреждением. Объём текста ограничен
`max_context_chars`, последние занятия имеют приоритет.

Поиск выполняется точно по косинусному расстоянию с фильтрацией ученика до LIMIT;
приближённый векторный индекс для небольшого MVP пока не нужен. Провайдер, модель,
размерность и версия подготовки текста сохраняются с каждым фрагментом.
Несовместимые индексы исключаются из поиска и учитываются как требующие
переиндексации. Размерность в БД переменная, поэтому для смены размера отдельная
миграция не нужна.

### Подготовка текста и ограничения проверки

В облако передаются только учебные поля и поисковый запрос, без UUID и дат.
Известные имена ученика и контактов заменяются; email и телефоноподобные строки
маскируются и в заметках, и в запросах. Полные объекты контактов и телефоны из
таблицы контактов провайдеру не передаются. Это базовая маскировка: она не
распознаёт произвольные имена, склонения, адреса и все идентификаторы свободного
текста. Для облачного прототипа используйте обезличенные или вымышленные записи.
После изменения известных имён пересоздайте индекс через `--force`.

Автоматические тесты используют детерминированный embedding-адаптер и HTTP-моки:
проверяют SQL-фильтрацию, ранжирование, миграции, обновление/удаление, несовместимые
модели и ошибки квоты без отправки данных в облако. Они не подтверждают качество
настоящей Gemini-модели. Для его оценки добавлен набор `data/retrieval_eval.json`:
нужно проиндексировать демоданные настоящей моделью и сравнить ожидаемые источники
с результатами запроса без последних занятий (`recent_lessons_limit=0`).

Запуск оценки после seed и переиндексации (расходует бесплатную квоту запросов):

```bash
docker compose exec api python -m app.evaluate_retrieval
```

Команда выводит найденные ID, recall и precision для каждого запроса. Это небольшой
стартовый набор, а не полноценная оценка качества: в нём всего шесть занятий.

### Модульное сопоставление людей и маскировка

Подготовка текста разделена на независимые части:

- `app/services/privacy.py` загружает из БД каталог выбранного ученика и его
  контактов: тип сущности, ID и имя. Телефоны не загружаются.
- `app/privacy/people.py` задаёт интерфейс `PersonResolver`: свободный текст и
  каталог людей превращаются в упоминания с границами текста и ссылками на ID.
  Текущий `ExactNameResolver` ищет только известные полные имена и их части без
  учёта регистра. Склонения и неизвестные имена пока не распознаются.
- `app/privacy/text.py` содержит общий путь маскировки. Он принимает найденные
  упоминания или готовые ссылки с ID, проверяет принадлежность каталогу ученика,
  границы и отсутствие пересечений, заменяет упоминания на `[имя]`, а затем
  маскирует email и телефоноподобные строки.

Свободный текст проходит путь `имя → PersonResolver → упоминание с ID → маскировка`.
Структурированный ввод проходит путь `готовое упоминание с ID → маскировка` и
обходит распознавание. Готовое упоминание задаёт `start`, `end` (индексы символов
исходной Python-строки) и ссылку `kind` + `id`. Это внутренний контракт для будущего
редактора; публичный JSON API занятий пока принимает обычный текст.

Если одно имя соответствует нескольким людям, компонент возвращает все варианты,
не выбирает произвольный ID и маскирует упоминание целиком. Сопоставление не
изменяет записи людей в базе. Новый распознаватель можно передать в
`TextAnonymizer` через интерфейс `PersonResolver`, сохранив общую обработку.

Версия подготовки текста повышена до `v2`. Для ранее созданных индексов запустите
`python -m app.reindex`; старые версии будут автоматически выбраны для обработки.
