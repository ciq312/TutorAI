# Tutor RAG

Помощник репетитора для быстрой подготовки к занятиям, составления домашних заданий и обратной связи после урока с учётом истории конкретного ученика.

Семантический поиск находит связанные темы и трудности в прошлых занятиях, а LLM использует этот контекст для подготовки черновиков материалов. Репетитор проверяет и редактирует результат.

## Основные сценарии

- **Перед занятием:** получить краткий бриф по ученику и план следующего урока с учётом целей, последних занятий и прошлых трудностей.
- **Домашнее задание:** подготовить задания по пройденным темам с учётом уровня ученика и ошибок, которые стоит отработать.
- **После занятия:** превратить короткие заметки репетитора в понятный фидбек для ученика или родителя.

Подробные сценарии, границы MVP, архитектура, модель данных и план разработки описаны в [PROJECT.md](PROJECT.md).

## Текущее состояние

Реализован первый этап — основа и данные:

- CRUD учеников, необязательных контактов и занятий через REST API и Swagger UI.
- История занятий по ученику, фильтрация по датам и пагинация.
- PostgreSQL, асинхронный SQLAlchemy и миграции Alembic.
- JSON-импорт демоданных и проверка доступности базы через `/health`.
- Интеграционные тесты на PostgreSQL.

Семантический поиск, LLM и генерация материалов пока не реализованы.

## Запуск через Docker Compose

Нужны Docker и Docker Compose.

```bash
cp .env.example .env
# При необходимости измените параметры PostgreSQL в .env.
docker compose up --build -d
```

При запуске API автоматически выполняет `alembic upgrade head`. Если миграция завершается ошибкой, API не стартует. Данные PostgreSQL сохраняются в Docker volume.

- Swagger UI: http://localhost:8000/docs
- OpenAPI: http://localhost:8000/openapi.json
- Проверка API и БД: http://localhost:8000/health

Загрузить вымышленные примеры (2 ученика, 2 контакта, 6 занятий):

```bash
docker compose exec api python -m app.seed
```

Повторный импорт пропускает существующие ID и не перезаписывает правки. Можно передать путь к другому JSON в формате `data/seed.json`. Импорт валидируется и выполняется одной транзакцией.

Остановить сервисы с сохранением данных:

```bash
docker compose down
```

## Локальная разработка

Нужны Python 3.14 и PostgreSQL. Для запуска Python на хосте можно поднять только базу через Compose:

```bash
cp .env.example .env
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
docker compose up -d db
alembic upgrade head
uvicorn app.main:app --reload
```

Если `.env` уже существует, сохраните свои настройки. Для запуска на хосте `DATABASE_URL` должен указывать на `localhost`; внутри Compose адрес `db` устанавливается автоматически. При изменении пароля или имени базы согласуйте значения `POSTGRES_*` и `DATABASE_URL`. Учётные данные существующего PostgreSQL volume не меняются простым редактированием `.env`.

## Работа с API

В Swagger сначала создайте ученика через `POST /api/students`:

```json
{
  "name": "Анна",
  "grade": "8 класс",
  "goals": "Уверенно решать квадратные уравнения"
}
```

Используйте полученный `id` для `POST /api/students/{student_id}/lessons`:

```json
{
  "scheduled_at": "2026-11-14T16:00:00+03:00",
  "topic": "Квадратные уравнения",
  "notes": "Разобрали дискриминант и решили три примера.",
  "difficulties": "Теряет знак при подстановке коэффициентов.",
  "homework": "Решить пять уравнений из выданного списка."
}
```

Контакты добавляются отдельно через `POST /api/students/{student_id}/contacts`: `name`, `phone` в международном формате (например, `+12025550101`), необязательное `relationship`. Ученик может существовать без контактов.

История — `GET /api/students/{student_id}/lessons`. Она отсортирована от новых занятий к старым. Параметры `date_from` и `date_to` включают границы и требуют часовой пояс. Все списки поддерживают `limit` (1–100, по умолчанию 50) и `offset`.

В `PATCH` пропущенные поля сохраняются, а `null` очищает необязательные. `homework` означает фактически заданное ДЗ; его выполнение пока не отслеживается. Удаление ученика удаляет его контакты и занятия. Несуществующие записи возвращают `404`, неверные входные данные — `422`.

## Тесты

```bash
pip install -r requirements-dev.txt
createdb -h localhost -U tutor tutor_test
TEST_DATABASE_URL=postgresql+asyncpg://tutor:change_me@localhost:5432/tutor_test pytest -q
```

Создайте отдельную тестовую базу с подходящими учётными данными. Имя обязательно должно начинаться с `tutor_test`: тесты откатывают миграции и очищают таблицы этой базы. Не используйте базу с рабочими данными. Без `TEST_DATABASE_URL` интеграционные тесты пропускаются.

## Данные и приватность

Имена и контакты хранятся в собственной PostgreSQL. Контакты доступны через отдельные endpoints и не включаются в ответы с учебной историей. В будущем перед отправкой внешним AI-провайдерам будет формироваться контекст без ненужных персональных данных, включая сведения из свободного текста заметок. При использовании облачных LLM или embeddings соответствующие тексты передаются внешнему провайдеру; локальное хранение само по себе не означает локальную обработку.

Первый MVP рассчитан на личный запуск одним репетитором в доверенной среде. Авторизация и несколько пользователей запланированы отдельно.
