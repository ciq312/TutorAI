# Google Calendar, Telegram и база знаний

Реализовано для существующего режима **одного репетитора в доверенном локальном окружении**. Веб-приложение не имеет авторизации: не открывайте API в интернет без отдельного слоя авторизации. Google OAuth подключает календарь, а не добавляет вход в наше приложение.

## Запуск

Установите зависимости, примените миграции и запустите API и отдельный worker:

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/alembic upgrade head
.venv/bin/uvicorn app.main:app --reload
# В другом терминале:
.venv/bin/python -m app.worker
# Интерфейс, ещё один терминал:
cd frontend
npm run dev
```

В Docker Compose API применяет миграции; worker запускается после успешной проверки здоровья API:

```bash
docker compose up --build -d
```

Worker нужен для синхронизации Google каждые пять минут, чтения команд подключения Telegram, обработки загруженных документов, индексации импортированных занятий и доставки сообщений. Интервал его основного цикла — `WORKER_INTERVAL_SECONDS`, по умолчанию 30 секунд. Браузер можно закрыть. Одновременный запуск двух worker предотвращён advisory lock PostgreSQL. Статус и время последней активности видны в настройках.

## Google Calendar

1. В Google Cloud создайте OAuth Client типа Web application и включите Google Calendar API. Настройте OAuth consent screen; для режима тестирования добавьте свой Google-аккаунт в test users.
2. Зарегистрируйте redirect URI, точно совпадающий с `GOOGLE_REDIRECT_URI` (по умолчанию `http://localhost:8000/api/integrations/google/callback`). При удалённом запуске адрес должен быть доступен браузеру пользователя.
3. Добавьте в локальный `.env` `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` и постоянный `INTEGRATION_ENCRYPTION_KEY`. Создайте ключ один раз:

   ```bash
   .venv/bin/python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
   ```

   Не храните ключ в Git и не меняйте его при перезапуске. OAuth access/refresh tokens шифруются этим ключом в PostgreSQL и не возвращаются через API. При смене ключа нужно переподключить Google.
4. Перезапустите API и worker. Откройте «Настройки → Google Calendar → Подключить Google» и подтвердите доступ. Возврат из OAuth защищён одноразовым state и HttpOnly-cookie.
5. Выберите календари, укажите «Смешанный» или «Занятия с учениками», сохраните выбор и нажмите «Синхронизировать».

Запрашиваются `calendar.calendarlist.readonly` и `calendar.events`: список календарей и чтение/редактирование событий. Право записи необходимо для добавления принятого ДЗ. Для календарей с ролью reader запись недоступна. Отключение удаляет локальные токены; доступ приложения в Google-аккаунте можно отозвать отдельно.

### Привязка событий

В календаре приложения появляется раздел событий Google. Название помогает предложить ученика, но окончательное решение принимает репетитор: существующий ученик, новый ученик или «Не занятие». Личные события не создают учебную историю и сообщения Telegram. Календари обоих типов требуют первоначальной привязки: режим «Занятия» обозначает назначение источника, не доказывает личность ученика.

Для повторяющегося события можно привязать всю серию. Сохраняются идентификаторы календаря, события и серии; будущие экземпляры привязываются по сохранённому правилу. Каждый экземпляр имеет собственное занятие, результаты и ДЗ. Переносы и отмены обновляют расписание и очередь сообщений; прошлые результаты не удаляются. События на весь день видны во входящих, но не превращаются в занятия без точного времени. Поддерживаемая длительность занятия — 10–240 минут.

Импорт использует полную пагинацию скользящего окна **30 дней назад — 180 дней вперёд**; ранее импортированные пропавшие события проверяются отдельно. Это намеренный простой polling без Google push/webhook и без смешивания временных фильтров с syncToken. Переносы в приложении пока меняют только локальное занятие; для привязанных событий переносите время в Google, который является источником расписания. Следующая синхронизация восстановит время Google.

### ДЗ в календаре

В карточке занятия → «Для ученика» доступно «Добавить принятое ДЗ в Google Calendar».

- Предварительный просмотр показывает название, время и **новое описание целиком**. Создание просмотра ничего не меняет в Google.
- Подтверждение действует 15 минут и связано с точной версией принятого ДЗ и ETag события. Изменившееся ДЗ или событие требует нового просмотра.
- Изменяется один экземпляр события, только поле description. Исходное описание сохраняется; блок `[My Tutor AI — ДЗ]` заменяется, а не добавляется повторно.
- PATCH использует `If-Match`. Повторное подтверждение безопасно, включая восстановление после успешной записи в Google и прерванного локального commit.
- Описание может быть видно участникам события. Решения для преподавателя не включаются. `sendUpdates=none` не рассылает приглашения/обновления участникам.

Здесь обычные API и подтверждение через БД; tool calling, LangChain и LangGraph не требуются. Управление действиями свободными командами чата пока не добавлено.

## Telegram

1. Создайте бота через BotFather и сохраните токен в `TELEGRAM_BOT_TOKEN` локального `.env`.
2. Установите `PUBLIC_APP_URL` в адрес нашего интерфейса. Для кнопки открытия занятия в Telegram нужен публичный HTTPS URL; локальные HTTP-ссылки в inline-кнопки не помещаются.
3. Перезапустите API и worker. В настройках нажмите «Подключить бота», откройте появившуюся ссылку и нажмите Start, затем «Проверить подключение».
4. Привязка принимается только из личного чата по одноразовому коду со сроком 10 минут. Ввод произвольного chat_id не предусмотрен. Другой poller или webhook этого бота нужно отключить: используется getUpdates.
5. Настройте бриф за N минут, результаты после принятия и напоминание заполнить итоги. Укажите часовой пояс IANA, например `Europe/Minsk`. Сохранение настроек серверное, независимо от браузера. В отдельном занятии можно отключить сообщения.

Бот пишет **репетитору**; отправка ученикам и родителям не реализована. Бриф использует сохранённый план/бриф прошлого принятого результата, актуальное предыдущее ДЗ и явно отмеченный статус его выполнения. Если данных нет, сообщает об этом. Новая LLM-генерация ради отправки не запускается.

После занятия сначала сохраните фактические заметки, затем нажмите «Сформировать результаты». Проверьте выжимку, ДЗ, решения, следующий план и будущий бриф. Только «Принять результаты и сохранить ДЗ» делает результат готовым к отправке. Время окончания урока само по себе не отмечает занятие проведённым и не создаёт выдуманных результатов. Фидбек остаётся запросом в чате.

Для брифов и напоминаний используется время занятия; для результатов — версия принятого текста. Outbox хранится в PostgreSQL и переживает перезапуск. Подтверждённые отправки не повторяются. При таймауте или прерывании отправки запись остаётся `uncertain`/`sending`: Telegram не предоставляет универсального ключа идемпотентности для sendMessage, поэтому автоматически повторять такой запрос нельзя без риска дубля. В настройках показывается проблема; проверьте чат и нажмите ручной повтор (не раньше двух минут после начала отправки). Очередь отменяет устаревшие сообщения перенесённых/отменённых занятий. Длинные сообщения ограничены 4000 символами; полный материал доступен в карточке. Worker не восстанавливает все старые уведомления после длительного простоя: бриф актуален до начала, напоминание — в течение шести часов после своего времени, результаты — для занятий за последние сутки.

## База знаний и КТП

Откройте вкладку «База знаний»:

- Загрузка PDF с текстовым слоем или TXT UTF-8 до 15 МБ. Максимум 500 страниц и 1 млн извлечённых символов. Сканам требуется предварительный OCR; отсутствие текстового слоя отображается как понятная ошибка.
- Типы: КТП, учебник/сборник, методика, собственный материал.
- Фоновая индексация по страницам через существующий embedding-адаптер и pgvector. Доступны статусы, ручная переиндексация, удаление и исходный файл.
- Поиск возвращает фрагмент, название и страницу. Такие же источники доступны в материалах занятия, результатах и чате как `[К1]`, `[К2]`. Это источники упражнений, а не доказательство прогресса ученика.
- У КТП можно извлечь черновик тем с помощью ИИ, отредактировать порядок/цели/страницы и явно сохранить проверенный список. При извлечении используется до 50 тыс. символов документа; при усечении интерфейс предупреждает о проверке полноты.
- Проверенный КТП назначается ученику вместе с текущей темой. Продвижение темы делает репетитор; завершение занятия не означает автоматического освоения материала.
- Изменения КТП, которые разрушили бы текущие назначения, блокируются. При удалении документа удаляются его индекс и назначения ученикам.

В этой версии оригиналы документов и извлечённые страницы хранятся **в PostgreSQL**, вместе с остальными данными приложения. Это сохраняет файлы при перезапуске и позволяет делать единый backup; отдельный S3-сервис пока не добавлен. Для больших библиотек потребуется вынести оригиналы в объектное хранилище. Облачные embeddings/LLM получают подготовленный текст с существующей базовой маскировкой известных имён, email и телефонов; ограничения маскировки остаются прежними. Календарные описания и личные события в LLM не передаются.

## Проверка

```bash
TESTCONTAINERS_RYUK_PRIVILEGED=true .venv/bin/python -m pytest -q
cd frontend
npm run build
npm test
```

Ryuk privileged требуется на Fedora с SELinux; на остальных системах переменную можно опустить. Тесты используют временную PostgreSQL и подменённые HTTP-ответы Google/Telegram, не обращаются к реальным аккаунтам и не отправляют сообщения. Сквозная проверка OAuth, доступов выбранного календаря и реальной доставки требует настроенных аккаунтов. Первое подключение выполняется пользователем через интерфейс.

Официальные контракты: [Google OAuth](https://developers.google.com/identity/protocols/oauth2/web-server), [Google Events patch](https://developers.google.com/workspace/calendar/api/v3/reference/events/patch), [Google synchronization](https://developers.google.com/workspace/calendar/api/guides/sync), [Telegram Bot API](https://core.telegram.org/bots/api).
